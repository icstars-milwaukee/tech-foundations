# PR Review Checklist

Use this before you click "Create Pull Request" — and when reviewing a teammate's.

## Before you open your PR
- [ ] **Branch name is clear** — describes the work (`add-login-form`, `fix-readme-typo`), not `test` or `stuff`.
- [ ] **Changes are small** — one focused task per PR. Easier to review, easier to fix.
- [ ] **Commit messages are meaningful** — each says what changed (`Add contact section`, not `update`).
- [ ] **You pulled the latest `main`** before pushing, to reduce conflicts.
- [ ] **The PR is linked to an issue** — type `Closes #3` in the PR description.
- [ ] **You requested a reviewer.**

## When reviewing someone else's PR
- [ ] Does the branch name make sense?
- [ ] Is the diff small enough to actually read?
- [ ] Do the commit messages explain the work?
- [ ] Is it linked to an issue?
- [ ] Leave one specific, kind comment — approve or request changes.

## The habit
**No PR without an issue. No merge without a review.**
This is what separates a professional repo from a messy one.
