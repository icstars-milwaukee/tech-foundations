# PR Review Checklist

Use this before you click "Create Pull Request" and when reviewing a teammate's work.

## Before you open your PR

- [ ] **Branch name is clear** — it describes the work (`add-login-form`, `fix-readme-typo`) instead of vague names like `test` or `stuff`.
- [ ] **Changes are small and focused** — one task or fix per PR makes review easier and reduces mistakes.
- [ ] **Commit messages are meaningful** — each one explains what changed, such as `Add contact section`, not `update`.
- [ ] **You pulled the latest `main`** before pushing to avoid unnecessary merge conflicts.
- [ ] **The PR is linked to an issue** — add a note like `Closes #3` in the description.
- [ ] **You requested a reviewer.**

## When reviewing someone else's PR

- [ ] **The branch name makes sense** — it reflects the purpose of the change.
- [ ] **The diff is small enough to read carefully** — avoid giant PRs that are hard to review.
- [ ] **The commit messages explain the work** — they should be understandable without guessing.
- [ ] **The PR is linked to an issue** — the change should be traceable and purposeful.
- [ ] **You leave one specific, kind comment** — either approve it or request changes with clear feedback.

## The habit

**No PR without an issue. No merge without a review.**

This is what separates a professional repo from a messy one.
