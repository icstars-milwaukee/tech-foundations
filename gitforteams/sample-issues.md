# Sample Issues to Pre-Create

Create these in the training repo's **Issues** tab before Guided Practice so every intern has
something real to link their PR to. GitHub automatically numbers them (#1, #2, …).

Interns can link a PR by writing `Closes #N` in the PR description.

---

## Issue 1 — Add your rule to `team-rules.md`

> Every team member should add one working-agreement line to `team-rules.md` and sign it.
> Labels: `good first issue`

## Issue 2 — Fix the placeholder in `team-rules.md`

> Remove the "add your rule here" placeholder line once real rules exist.
> Labels: `cleanup`

## Issue 3 — Decide the team's favorite language (`conflict-lab.md`)

> Update the language line in `conflict-lab.md`. Note: multiple people editing this file creates a merge conflict — that is intentional.
> Labels: `conflict-lab`

## Issue 4 — Improve the README

> Add a short "About our team" section to `README.md`.
> Labels: `enhancement`, `good first issue`

## Issue 5 — Fix a typo

> Find and fix any typo anywhere in the repo. This is a small PR practice exercise.
> Labels: `good first issue`

---

## Facilitator tip

Assign issues loosely — it's fine if two interns choose the same one. For the conflict lab,
intentionally allow overlap on Issue 3.
